## 独立复核

在全新上下文中，完整阅读 Spec、可选测试数据、测试用例及其澄清问题、[to-testcase](../to-testcase/SKILL.md) 和它链接的测试用例示例。不要查看实现代码或既往复核结果。

## 复核内容

- 进行双向核对：将每项可确定且在范围内的 Spec 规则和明确列出的成员映射到用例、数据行或准确的澄清问题；同时确认每项预期结果都有 Spec 依据、可建立的前置条件，以及可观察且具有判别力的结果。
- 查找实质重复项，并检查优先级，以及是否符合好用例的特征、避开坏用例的警示。
- 只有 Spec 定义了交互，或者组合能暴露一种不同的可信缺陷时，才要求组合覆盖；明确列出的成员不意味着必须生成笛卡尔积。

## 报告结果

只报告可能误判实现、阻碍执行、遗漏明确覆盖、虚构行为或明显造成优先级失真的实质缺陷。普通业务前置状态未说明创建步骤，不属于缺陷。

不要修改用例。若未发现实质缺陷，返回 `PASS`；否则返回 `FAIL`，并针对每项问题列出受影响的用例或覆盖项、违反的 Spec 或规则、影响及修正方式。区分生成缺陷与 Spec 或测试能力缺口。
